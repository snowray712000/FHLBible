## What the old screen did
- Storyboard scene `VCAudioBible` (+ orphan `UINavigationController` scene): play / prev / next / loop-mode icon buttons, a speed button (modal picker `VCPlayrate`: 2.0x 1.5x 1.25x 1.0x 0.75x 0.5x), a version button (modal picker `VCAudioVersion`, title = version name), a timer button (modal `VCAudioStopTimer`), a `UISlider` progress bar with elapsed / remaining labels, and a right bar item with the "book-chap" title. Slider `valueChanged` seeked continuously with zero tolerance.
- viewDidLoad logic (all kept): show version name / title / countdown; `loopMode = DAudioBible.s.loopMode`; on 2nd entry (`AVPlayer.s != nil`): if the same chapter is already loaded -> restore slider max, enable prev/next, play icon from `DAudioBible.s.isPlaying`; otherwise reset slider, disable prev/next, `AVPlayer.s.rate = 0`, then `AudioBibleSetter.s.trySetDAudioBibleAddrAndMp3(DAddress(book,chap,1), versionIdx)`; on 1st entry just add the callbacks and call trySet. `DBackgroundMusic.s.tp = .bible` (so the control center targets this source). Callbacks (via `VCAudioBibleEvents`, key per instance): checking-address (disable everything), checked-address (mp3 found -> `EasyAVPlayer.s.replacePlayer(mp3)` and remember book/chap; not found -> disable controls and show "無此章節"), searching/searched next, searching/searched prev (disable/enable that button + loop + version), ready-to-play (set book/chap, enable play, slider max = duration, auto-play when `DAudioBible.s.isPlaying && rate == 0`), 0.5 s tick (slider), stop-timer tick/completed. On `willResignActive` the callbacks are released, on `didBecomeActive` book/chap/title/countdown are refreshed and callbacks re-added.
- Chapter data model: one mp3 per chapter; `AudioBibleVersions` maps version id <-> name (localized string "0.和合本 1.台語 ... 17.現代台語譯本"), `AudioBibleSetter` finds current/next/prev mp3 (loop mode aware), `EasyAVPlayer` owns the single `AVPlayer.s` and the remote-command / now-playing integration. None of this changed.

## What changed
- `VCAudioBible/VCAudioBible.swift` rewritten:
  - `class VCAudioBible: UIHostingController<AudioBibleView>`, `init(book:chap:)`; `init(coder:)` is `fatalError`.
  - `@Observable AudioBibleModel` (conforms to `AudioTimerProviding`): holds book, chap, isPlaying (= pause icon shown), versionIdx, speed, loopMode, timerText / isTimerRunning, statusText ("無此章節"), position / duration / isScrubbing, enabled flags (play, prev, next, loop, version). `init` is the old viewDidLoad (same 1st / 2nd-entry branches, with optionals instead of `!`). Actions keep the old semantics: `playOrPause` (no player yet -> `replacePlayer(mp3)` and `rate = speed`; playing -> `pause()` + `DAudioBible.isPlaying = false`; else `rate = speed` + `isPlaying = true`), `goNext/goPrev` (`EasyAVPlayer.goNext/goPrev`, then re-read book/chap), `setSpeed` (live `rate` change only when currently playing, store in `DAudioBible.s.speed`), `setLoopMode` (`findWhenSetLoopMode(new, old)` BEFORE storing, then store), `setVersion` (no-op if same; async `trySet...` with the new index, then `DAudioBible.s.versionIndex`), `seek`, `startStopTimer(minutes:)` (`AudioBibleStopTimer.s.stopPrevTimerAndStartNewTimer(min*60)`), `cancelStopTimer()` (`cancelTimer()`, `secondRemainForStopTimer = 0`; if a timer was running `cancelTimer` triggers evCompleted, whose built-in handler sets `AVPlayer.s.rate = 0`, so cancelling pauses - existing quirk). Callbacks are re-bound with `events.releaseEvents()` first (idempotent); `willResignActive()/didBecomeActive()` replace the `EasyEventAppBackgroundForegroundSwitch` usage and are driven by `scenePhase` (`.active` vs anything else). `didBecomeActive` also reloads the duration (the old screen could keep a stale slider max after a track change in the background).
  - `AudioBibleView`: book symbol (`symbolEffect(.pulse, isActive: isPlaying)`), "書卷 章" large title, version `Menu` (Picker of all 17 versions with a checkmark, label = name + up/down chevron), progress (`Slider` + elapsed left / "-remaining" right, seek on release, thumb follows playback unless scrubbing; "-- : --" until the duration is known), transport (prev / 72pt play-pause / next, each disabled per the flags), three tiles: loop `Menu`+`Picker` (連續播放 / 本卷循環 / 單章重複), speed `Menu`+`Picker` (same 6 speeds; tile shows "1.25x"), stop-timer `Menu` (cancel item only while running + the 8 durations). Inline title "有聲聖經".
  - Shared with the text player (moved here, `VCAudioTextBible.swift` now uses them): `AudioOptionLabel` (tile look), `audioStopTimerMinutes`, `audioStopTimerMinutesTitle(_:)`, `AudioTimerProviding` + `AudioTimerTile` (renders the live countdown). `AudioTextBibleModel` also got `isTimerRunning`.
- Unchanged and now unused by any screen: `VCAudioStopTimer`, `VCPlayrate` (only its `speed` array is used), `VCAudioVersion` (only `AudioBibleVersions` in the same file is used), `IVCAudioBibleEvents`/`VCAudioBibleEvents` are still used (model owns an instance). Not deleted (maintainer decides).
- `Read/VCRead.swift`: `VCAudioBible(book: addr.book, chap: addr.chap)`; `VCEasyFunctions.swift`: `gVCAudioBible()` removed (no other users).
- `Base.lproj/Main.storyboard`: removed scene `5BM-B0-Srd` (VCAudioBible, 7 buttons, 3 labels, slider, outlets) and orphan nav-controller scene `cT6-Pt-mpC` (`Wod-xl-srh`). 28 -> 26 scenes (working tree). ## Gotchas (SwiftUI + Observation)
- A `Menu` closes itself when its parent view re-evaluates `body`. The 0.5 s progress tick and the 1 s countdown tick therefore must be read ONLY inside small child views (`AudioBibleProgressView` with `@Bindable`, `AudioTimerTile`), and the menu content must depend on a flag that changes rarely (`isTimerRunning`), not on `timerText`/`position`. Before this split every tick dismissed an open speed menu.
- A custom `LabelStyle` on a `Menu` label made the version menu silently refuse to open on iOS 27 (no error); a plain `HStack` label works. Add `.contentShape(Rectangle())` and padding for a decent hit area.
- Observation macro: `@Observable` stored properties can have `didSet`, but assignments inside `init` don't trigger it; the old `loopMode` didSet side effects are therefore explicit `setLoopMode`.
- `Slider(value: $model.position, ..., onEditingChanged:)` with an `@Observable` model needs `@Bindable var model` in the child view.
- `CMTime.seconds` can be NaN/inf before the item is ready; `ctime2dashdashformat(Double)` crashes on NaN (`Int64(NaN)`), so only finite positive durations are stored.
