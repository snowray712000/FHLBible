## Goal / why
After 1023d the only things left in `Main.storyboard` were three scenes loaded by storyboard identifier: `VCSnActionPicker`, `VCVerseActionPicker` (both `UITableViewController`s on FHLCommon's `VCPickerBaseOnTableView<T>`, shown with FHLCommon's custom half-screen presentation) and `VCWhenLongPress` (+ an orphan nav controller; a UITextView + a collection view of cells with help button / action button / switch). ## Design
### Generic action picker (`FHLTools/VCSnActionPicker.swift`)
- `ActionPickerItem<Action>` {title, detail, systemImage, action}; `ActionPickerView<Action>` = `NavigationStack { List }` with inline title, a "取消" toolbar button, each row = SF Symbol + headline title + footnote detail.
- `UIViewController.presentActionPicker(title:items:onPick:)` wraps it in a `UIHostingController`, `.pageSheet` with `sheetPresentationController.detents = [.medium(), .large()]`, grabber visible. Picking calls `dismiss(animated:)` and runs `onPick` in the **completion** (so the follow-up push happens after the sheet is gone); cancel / swipe-down never calls `onPick`. The hosting controller is reached from SwiftUI closures through a weak box (`ActionPickerHostBox`) to avoid a retain cycle.
- `presentSnActionPicker(sn:onPick:)`: items 彙編(.list, list.bullet) / Parsing(.parsing) / CBOL(.cbol) / 浸宣(.twcb); same four as before (`.dict` and `.cbole` stay hidden); title = `dtext.tp + dtext.sn`, e.g. "G1223". `SnDTextClickFlow.mainAsync` now uses it (same dispatch: list -> `VCSearchResult`, parsing -> `VCParsing`, others -> `VCSnDict`).
- `presentVerseActionPicker(title:onPick:)` in `Read/VCVerseActionPicker.swift` (enum `VerseAction` kept there): 譯本比較 / Parsing / 註釋 / 串珠. Only caller is `OneVerseFunctionsClickFlow.mainAsync(_ addr:)`, which itself has no callers any more (Read and Search results use their own `confirmationDialog` with the same four actions). Kept, compiled, not exercised.
- Removed `gVCSnActionPicker/gVCVerseActionPicker/gVCWhenLongPress`, `gEasyGetViewCtrlFromXibCore` and `easyGetViewCtrlFromXibCore` from `VCEasyFunctions.swift` (no storyboard left; nothing else used them).

### Copy / image screen (`VCWhenLongPress/VCWhenLongPress.swift`)
- Entry: `VCRead.confirmSelection()` -> `push(VCWhenLongPress(dataSelections: model.makeSelections()))` (`DSelections` unchanged: `addrs`, `vers`, `data[[DAddress]][ver] = [DText]`).
- `VCWhenLongPress: UIHostingController<CopyShareView>`, model `CopyShareModel` (`@Observable`): options `isSNShow` (true), `isGenerateAddress` (true), `isForceShowVersion` (false); `content: NSAttributedString` regenerated by `regenerate()` (generation counter +1) whenever a toggle changes. Content generation is the old `generateTextViewContent` verbatim in behavior: per address block "#徒 28:1|" title in blue, then one paragraph per translation (blank line between), "(譯本名)" blue suffix when >1 translation or forced, blocks separated by blank lines, and a trailing red "[#<addrs>|]( https://bible.fhl.net/NUI/_rwd/#/bible/<addrs, ';'->'.' percent-encoded> )" with a `.link` attribute when `isGenerateAddress`. Fixes: `1..<title.count` crash on empty title replaced with append-all; empty `DSelections` no longer crashes.
- Text box: `UITextView` in a `UIViewRepresentable` (`CopyTextView`), **editable** like before (user can annotate before copying); `TextEditor` was rejected because on iOS 17 it cannot hold a coloured/linked `NSAttributedString`. The view resets `attributedText` only when `generation` changes (otherwise typing would be wiped). Keyboard: `keyboardDismissMode = .interactive`, an `inputAccessoryView` UIToolbar with "完成", and `.scrollDismissesKeyboard(.interactively)` on the List.
- Layout: inset-grouped `List`: section "內容（可直接修改）" (240 pt text box), section "複製" (純文字複製 / 進階複製 / 圖片複製 / 圖片產生, help text shown under the title instead of the old "?" button + alert), section "內容選項" (three `Toggle`s with help text; footer warns that edits are lost on change). Nav title "複製與圖片" (was "長按動作"), trailing "複製" = copy everything.
- Copy semantics (changed on purpose): always copies the text box's **current** content. One pasteboard item holding several representations: `.text` -> `public.utf8-plain-text`; `.rtf` -> plain text + `public.rtf` (old code replaced everything with RTF only); `.img` -> `public.png`; `.all` -> text + rtf + png (old code appended three separate pasteboard *items*). Old 圖片複製 also called `UIImageWriteToSavedPhotosAlbum` (silent write to the user's photo library); that side effect was **dropped** - saving is the separate 圖片產生 action.
- Image rendering: no more `UIScrollView.capture` scroll-and-stitch on the visible box. `renderImage()` builds an off-screen non-scrolling `UITextView` (width = visible box width, min 320), forced light (`overrideUserInterfaceStyle = .light`, white background, rendered inside `UITraitCollection(userInterfaceStyle: .light).performAsCurrent`), height = `sizeThatFits`, drawn with `UIGraphicsImageRenderer` + `layer.render`; `format.scale = min(scale, max(1, 16000 / height))` (same cap as `ReadSnapshotRenderer`; select-all of a 31-verse chapter was 1029 x 16971 px at 3x before the cap).
- Save to album: `SaveToPhotoHelper` (kept alive in the model); its `evCompleted` callback is used so no alert is shown - result goes to the toast.
- Feedback: transient capsule toast (`model.toast`, auto-clears after 1.8 s via `DispatchQueue.main.asyncAfter`, a counter prevents an old timer from clearing a newer toast). Replaces the "文字已複製到剪貼簿中。" alert; strings reused.
- New zh-Hans Localizable keys: 複製與圖片, 內容（可直接修改）, 內容選項, 改變選項會重新產生上面的內容，之前所做的修改會消失。 (zh-Hant is the source language and has no entries for these keys).

`Base.lproj/Main.storyboard`: all `<scenes>` and `<resources>` removed; the file is now an empty, valid IB document (ibtool compiles it without warnings). pbxproj still lists the file and the three leftover swift files, and `zh-Hans/zh-Hant Main.strings` still exist (stale keys only). Not touched (do not hand-edit pbxproj): the maintainer should delete in Xcode: `Main.storyboard` (+ its Main.strings variants), `VCWhenLongPress/add_fns.swift`, `LongPressFuncCell.swift`, `DOneLongPressCellSetting.swift` (now comment-only stubs). `Info.plist` already had no reference to Main.storyboard (1023d).

## Verification
`xcodebuild -workspace FHLWorkSpace.xcworkspace -scheme FHLBible` succeeded for iPhone 15 Pro (iOS 17.4) and iPhone 13 mini (iOS 27.0). Run on iOS 27.0: tap an SN in Read -> sheet titled with the SN, 4 rows; cancel works; 浸宣/CBOL row dismisses then pushes the dictionary (checked CBOL, G1223); 選取經文 -> 全選 -> 完成 -> new copy screen with all sections; 純文字複製 put the expected text on the pasteboard (`xcrun simctl pbpaste`), toast shown; image renders correctly (checked a PNG dump: light background, coloured SN, links, whole chapter).
Not verified: saving to Photos - fails with "Unknown error" on this simulator **also for the untouched Read 圖片產生**, so it is a simulator/Photos limitation, not this change (never saw it succeed, so the 16000 px cap is untested against a real library); RTF/PNG pasteboard contents (only plain text read back); toggles regenerating content, editing the text then copying; verse action picker (`presentVerseActionPicker`, no live caller); iPad; dark mode; iOS 17.4 runtime (taps on the 17.4 sim did not register in this session, only the build was checked); the sheet's behaviour with Dynamic Type very large.
- Simulator tip (again): iPhone 13 mini taps must use screenshot-pixel x 375/923 (see 1021w). Screenshots from the control tool lag a second behind; for transient UI (toast) use `xcrun simctl io <udid> screenshot <file>` right after the tap.
