## Goal / why
User asked (starting from 4.12.16) to convert "搜尋ing" and "搜尋結果" to SwiftUI, free to redesign if it follows iOS guidelines better. After this, **no screen instantiates `ViewDisplayTable2` any more**; `ViewDisplayCell` survives only inside `DTextContentView`.

## Flow (unchanged contract)
`VCRead.doSearching()` pushes `VCSearching()`; on a pick `VCSearching` pops itself (`animated: false`, otherwise the result would be pushed on top of it) and fires `onClickSearching$: IjnEventOnce<UIView,DText>` (sender nil, `DText(keyword)`); `VCRead` then pushes `VCSearchResult(keyword:vers:addr:)`. `VCSearchResult(...)` is also pushed directly by `SnDTextClickFlow` (tap SN -> 彙編) and `VCSnDict.doSnList` (keyword = `tp + sn`, e.g. `H430`). `setInitData` and `gVCSearching()` / `gVCSearchResult()` no longer exist.

## "搜尋ing" screen (`Search/ViewSearching.swift` = `SearchingView` + `@Observable SearchingModel`; `VCSearching.swift` = hosting controller)
- `.searchable(text:isPresented:placement: .navigationBarDrawer(.always))` + `.onSubmit(of: .search)`; `isSearchPresented` is set true in `.task` so the field is focused on arrival (verified on iOS 27: cursor in the field). Note: while the search field is active iOS hides the nav bar items (incl. the trash button), hence a second "清除搜尋記錄" row at the end of the history list (shown only when the field is empty).
- History = `ManagerSearchHistory.s.cur` (`[String]`, newest first, UserDefaults key `SearchHistory`). `SearchingModel.commit(raw)` trims whitespace, rejects empty, moves/inserts the word at index 0, saves, returns the word. Old code did not reorder when tapping a history row; new code does. Swipe-to-delete one item (`remove`), clear all behind a `confirmationDialog`.
- While typing, history is filtered with `localizedCaseInsensitiveContains` and a first row "搜尋「xxx」" runs the search (same as the Return key).
- Empty state (no history, no text): `ContentUnavailableView` explaining space-separated keywords and SN input (`H430`, `G3056`).

## "搜尋結果" screen
Files: `Search/VCSearchResult.swift` (hosting controller `VCSearchResult`, `SearchResultModel`, `SearchResultView`, `SearchRowView`, private `SearchKeywordColorer`), `Search/ViewSearchFilter.swift` (`SearchFilterBar`, `extension SearchData.Filter: Identifiable` with `id = "\(na2)|\(na)"` — must be `public` because `SearchData.Filter` is public).
- Unchanged data layer: `SearchQ`/`ISearchQ` (se.php via `fhlSe`, 500 per page per translation; progress callback `(ver, count)` arrives on a background thread, finished callback on main), `DSearchResult`, `SearchData.Filter`, `DataForDrawTable`.
- `SearchResultModel` state: `phase` (.searching/.done), `foundCount` (sum of per-translation running counts, shown while searching), `totalCount`, `filters`, `group` (which tab of the filter bar is displayed) vs `selectedGroup`/`selectedOpt` (the applied filter), `rows: [SearchRow]` (`id` = index, `addr`, `address` text "創 1:3", `cells: [[DText]]?` nil until loaded), `filterToken` (bumped per filter change; `.id(filterToken)` on the `List` resets scroll to top), `isSnVisible` + `snGeneration`, `verseActionRow`.
- Filter semantics (ported verbatim from the old VC): `SearchFilterGroup` rawValues `"書卷"`/`"分類"` are internal data values (`Filter.na2`), displayed through `NSLocalizedString`. Book filters: one per book with hits, label = book name in `ManagerLangSet.curTpBookNameLang`. Classor filters: `ManagerLangSet.curBookClassorNaOrder` with count > 0 (includes "全部"). Initial selection = `DSearchResult.suggestClassor` (group 分類) else `suggestBook` (group 書卷) — i.e. the book you came from if it has more than 10 hits, else the smallest classor containing it with more than 10, else "全部". Applying: classor -> addresses whose book is in `curBookClassor[name]`; book -> `BibleBookNameToId().main1based(lang, name)`.
- Lazy loading: `rowAppeared(i)` requests rows `i-10 ..< i+30` that have no cells and were not requested in the last 15 s, via `DataForDrawTable.queryDataAsync(rows)` (which batches them into one `ReadDataQ` call: address string = `VerseRangeToString` of the rows' addresses). `onDatasGetter$` (any thread) -> `DispatchQueue.main.async` -> `absorb(table)` copies `table.datas[i].1` into `rows[i].cells`. Callback is registered once per `DataForDrawTable` (the old table registered a new callback per query). `DataForDrawTable._datasQuering` is never populated by its own code (`_updateDatasQueryWhenStartingOnce` is dead), so dedup lives in the model's `requested` dictionary. A new table is made on every filter change and the old one gets `isAlreadyNoUse = true`; `search()` also bumps `searchId` so a retried search drops stale callbacks.
- Keyword colouring (`SearchKeywordColorer.colorIt`, called by `DataForDrawTable` per loaded row, possibly off the main thread, mutates the `DText` objects in place before they are stored): SN keyword (`SnHelper.sn != nil`) -> in versions `unv`/`kjv` any DText with the same `sn` and `tp` gets `keyIdx0based = 0`; otherwise the keyword is split on spaces, each wrapped in `( )` and joined with `|` into a case-insensitive `NSRegularExpression`; every matching fragment is cloned into a child DText with `keyIdx0based = (matched group index) - 1` (colour = `UIColor.ijnKeywords[idx % 7]` in FHLCommon). Behavior change: an invalid pattern (keyword containing `(` etc.) used to `try!`-crash, now the row is simply not coloured.
- UI: nav bar principal = keyword (headline) + subtitle "搜尋中..." / "共 %@ 筆" (`Int.formatted()`); trailing = `Toggle("SN").toggleStyle(.button)`, disabled when none of `unv/kjv/rcuv` is in `vers`; `isSnVisible` starts true iff the keyword is an SN and is independent of the global `ManagerIsSnVisible` (as before: the old VC had its own `_isSn`). Filter bar is `.safeAreaInset(edge: .top)` on the `List`: segmented 分類|書卷 (128 pt) + horizontally scrolling capsule chips "name count" (selected = prominent tint, scrolled into view on appear / group change, `sensoryFeedback(.selection)`). `SearchFilterBar` reads only filter properties of the model so it does not rebuild while verses stream in.
- Row: address button (tint + chevron; `confirmationDialog` anchored on it with 譯本比較 / Parsing / 註釋 / 串珠 -> `VerseAction`, handled in `VCSearchResult.doVerseAction` exactly like `VCRead.doVerseAction`), then one `DTextContentView` per translation (`generation: snGeneration`, `onTapAny`), side by side when `horizontalSizeClass == .regular` and more than one translation, with a caption naming the translation when more than one. `cells == nil` shows a `ProgressView`; `DTextContentView` is only created once data exists, so `generation` only needs to change on the SN toggle.
- Taps in verse text: SN -> `SnDTextClickFlow(vc:addr: row.addr, vers:)`; ref -> `RefDTextClickFlow(vc:addr: model.addr (the verse we came from), vers:)`; footnote -> `FooterDTextClickFlow(vc:vers:).mainAsync(dtext, vers[col], row.addr)`.
- Empty result (`totalCount == 0`): `ContentUnavailableView` "找不到「kw」" + hint + 重試 (re-runs `search()`). `SearchQ` cannot tell "no hits" from "network failure" (a failed page just ends the loop). The old `fatalError("搜尋參數錯誤")` branch was unreachable and is gone.
- Dropped: the old top header row with translation names (now a caption per cell), the 3 pt-inset button row, `IjnEvent`-based redraw plumbing, `_resize_OnOff_Switch` / `IsOnOfSelectionsOfSwitch` (multi-select never existed in search).

## Gotchas
- Simulator tool: taps need screenshot px * 0.406 on the iPhone 13 mini (375x812 pt; the tool reports 360x780) and an explicit `device` for each call when two simulators are booted (otherwise taps go to the first attached one). The `text` action pastes via the clipboard and failed here; to test with other keywords use the launch-argument override instead: `xcrun simctl launch <udid> IJN.FHLBible -SearchHistory "(zzqxwv, H99999)"` (argument-domain UserDefaults beat the stored value; `simctl spawn ... defaults write` stopped taking effect after the first run).
- Screenshots right after a tap often show the previous state; wait and take a second one.
- `SearchData.Filter` is `public`, so the `Identifiable` conformance's `id` has to be `public`, otherwise the build fails.
- With `.searchable` active the nav bar contents are hidden by iOS 26; anything essential must also exist in the content.
- The first tap on 閱讀 after a cold launch can do nothing for a few seconds (network wait in `goRead`).
